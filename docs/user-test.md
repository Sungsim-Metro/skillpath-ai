# 사용자 테스트 진행안

이슈: [#39](https://github.com/Sungsim-Metro/skillpath-ai/issues/39) · 담당: 형섭 · 근거: [`planning-review-2026-11-11.md`](planning-review-2026-11-11.md) 디자인 씽킹 절, [11/12 멘토링](meetings/2026-11-12-mentoring.md)

두 단계로 한다. 화면이 없어도 되는 **사전 인터뷰**(11/14까지 2명)로 문제 한 문장을 확인하고,
M3 화면이 나온 뒤 **본 테스트**(11/18~20, 3~5명)로 화면을 보고 설명하게 한다.

| 단계 | 언제 | 몇 명 | 무엇을 얻나 | 평가 항목 |
| --- | --- | --- | --- | --- |
| A. 사전 인터뷰 | 11/14까지 | 2명 | 문제 한 문장의 "알고 보니" | 문제해결력, 현장 적용성 |
| B. 본 테스트 | 11/18~20 (M3 뒤, M4 전) | 3~5명 | 세 질문에 답할 수 있는 화면인지, M4 전에 고칠 것 1~2개 | 현장 적용성, 전달력, 수업 기준 "추천 성능" |

발표에는 사람 수와 들은 말을 그대로 적는다. 숫자나 반응을 지어내지 않는다.

## 공통 규칙

- **대상**: 클라우드·AI 엔지니어 취업을 준비하거나 고민 중인 대학생·졸업생. 팀원과 이 부트캠프 수강생은 제외한다(과제를 이미 알고 있다).
- **"괜찮아요?"라고 묻지 않는다.** 설명하게 하고, 막히는 곳을 본다. 진행자는 도와주지 않는다. 질문을 받으면 "어떻게 생각하세요?"로 돌려준다.
- **개인정보**: 이름, 학교, 연락처를 기록하지 않는다. P1~P5로 부른다. 녹음은 하지 않고 메모만 한다. 저장소는 제출 직전 공개되므로(#44) 한 사람을 알아볼 수 있는 내용(학교·회사 이름 등)은 적지 않는다.
- **동의**: 시작 전에 아래 문장을 읽어 주고 "네"를 받는다.
  > 공부할 기술을 추천하는 서비스를 만들고 있어 의견을 듣고 싶습니다. 10분 정도 걸립니다. 이름은 적지 않고, 하신 말씀은 익명으로 팀 문서와 발표 자료에 쓸 수 있습니다. 언제든 그만두셔도 됩니다.

## A. 사전 인터뷰 (11/14까지, 2명, 10분)

화면을 보여주지 않는다. 지난 경험을 듣는다. 의견("이런 서비스 있으면 쓸 거예요?")은 묻지 않는다.

1. 지금 어떤 직무를 준비하고 있나요?
2. 가장 최근에 "이걸 공부해야겠다"고 정한 적이 언제였나요? 무엇을 정했나요?
3. **그때 무엇을 보고 정했나요?** (공고, 선배, 유튜브, 커뮤니티, 부트캠프 커리큘럼 등)
4. 채용공고를 봤다면 몇 개쯤 봤나요? 어떻게 정리했나요?
5. 그렇게 정한 것이 맞았다고 생각하나요? 아니라면 언제 알았나요?
6. 그 과정에서 가장 시간이 많이 든 일이나 답답했던 일은 무엇인가요?
7. (AWS 과정을 모르는 경우만) AWS SkillBuilder 무료 과정을 들어본 적 있나요?

### 기록 양식

| | P-A1 | P-A2 |
| --- | --- | --- |
| 준비 직무, 학년·졸업 여부 | | |
| 최근 정한 공부 | | |
| 정할 때 본 것 (3번) | | |
| 공고를 본 개수와 정리 방법 (4번) | | |
| 틀렸다고 느낀 때 (5번) | | |
| 가장 답답했던 일 (6번, 들은 말 그대로) | | |

### 결과로 할 일
- 문제 한 문장 초안의 "알고 보니"가 들은 말과 맞는지 본다.
  > 클라우드 엔지니어를 준비하는 컴공 4학년은 채용공고를 보고 공부 계획을 세우려 했는데, 알고 보니 공고마다 표현이 달라 공통으로 요구하는 기술을 셀 수 없어서 자격증과 강의를 감으로 골랐다.
- 다르면 들은 말로 고친다. 고친 문장은 11/15 회의에서 확정하고 발표 첫 장에 쓴다.

## B. 본 테스트 (11/18~20, 3~5명, 한 사람당 10분)

### 준비
- 시연용으로 고정한 환경(#23)과 같은 화면을 쓴다. 진행 중에 코드를 고치지 않는다.
- 참가자가 자기 보유 기술을 직접 고른다. 진행자가 대신 고르지 않는다.
- 진행자 1명(질문), 기록자 1명(아래 양식). 비대면이면 화면 공유로 하고 참가자가 직접 조작한다.

### 진행 순서
1. (1분) 동의 문장 읽기. "정답은 없고, 화면이 잘 설명하는지 보는 시험입니다."
2. (1분) 목표 직무와 보유 기술을 직접 고르게 한다. 설명은 하지 않는다.
3. (각 2분) 세 과제를 순서대로 부탁한다. 생각을 소리 내어 말해 달라고 한다.
   - **과제 1**: "이 화면을 보고 다음 주에 무엇부터 공부할지 말해 주세요."
   - **과제 2**: "왜 그 과정이 추천됐는지 설명해 주세요."
   - **과제 3**: "이 기술이 필요하다는 근거가 어디 있는지 찾아 주세요."
4. (2분) 마무리 질문 두 개.
   - "이 화면에서 가장 헷갈렸던 곳은 어디였나요?"
   - "평소 공부할 것을 정하던 방법과 비교하면 무엇이 달랐나요?"

### 판정 기준 (기록자가 그 자리에서 표시)
| 과제 | 성공 | 부분 | 실패 |
| --- | --- | --- | --- |
| 1. 무엇부터 | 부족 기술 중 하나와 과정 하나를 말함 | 기술만, 또는 과정만 말함 | 말하지 못함 |
| 2. 추천 이유 | 수요(공고 n건 중 m건)나 추천 이유 문장을 근거로 설명함 | "AI가 추천해서" 수준 | 설명하지 못함 |
| 3. 근거 찾기 | 2분 안에 근거 보기에서 공고 문장을 찾음 | 도움 없이 찾았으나 2분 넘음 | 찾지 못함 |

### 결과 정리 (11/20 회의 전)
- `docs/user-test-results.md`에 사람별 기록과 과제별 성공 수(예: 과제 3 성공 2/4명)를 적는다.
- 두 명 이상이 같은 곳에서 막혔으면 그것을 M4 전에 고칠 것 1~2개로 정한다. 기능 동결(11/19) 뒤라면 화면 문구와 배치만 고친다.
- 발표 자료에는 "n명 중 m명"과 들은 말 1~2개를 넣는다. 고친 것이 있으면 고치기 전과 후를 함께 보여준다.
