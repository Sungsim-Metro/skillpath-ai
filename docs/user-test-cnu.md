## 4. 사전 설문 (구글 폼, 3분)

화면을 보여주지 않는다. "이런 서비스가 있으면 쓸 건가요?" 같은 의견은 묻지 않고, 지금까지 실제로 한 일을 묻는다.

**첫 화면 (동의)**
> 충남대 컴퓨터융합학부 학생 팀이 AI 부트캠프 경진대회 프로젝트를 위해 진행하는 설문입니다. 3분 정도 걸립니다.
> 이름과 학번은 받지 않습니다. 응답은 익명으로 집계해 팀 문서와 발표 자료에 씁니다. 언제든 그만둘 수 있습니다.
> ☐ 동의합니다 (필수)

| # | 질문 | 형식과 선택지 |
| --- | --- | --- |
| 1 | 학년 | 3학년 / 4학년 / 졸업 유예·졸업 / 그 외(설문 종료) |
| 2 | 관심 있는 직무 (모두 선택) | 클라우드·인프라 / AI·머신러닝 / 백엔드 / 데이터 / 프론트엔드 / 아직 못 정함 / 기타 |
| 3 | 지금 취업 준비는 어느 단계인가요 | 아직 시작 안 함 / 정보만 찾아보는 중 / 공부하는 중 / 지원하는 중 |
| 4 | 최근 6개월 안에 "취업하려면 이걸 공부해야겠다"고 정한 것이 있나요? 있다면 무엇인가요 | 주관식 한 줄 (없으면 "없음") |
| 5 | 그것을 정할 때 무엇을 봤나요 (모두 선택) | 채용공고 / 선배·동기 / 교수님·수업 / 유튜브·블로그 / 커뮤니티(에브리타임, 오픈채팅) / 부트캠프·강의 커리큘럼 / 자격증 정보 / 기타 |
| 6 | 최근 한 달 동안 끝까지 읽은 채용공고는 몇 건인가요 | 0건 / 1~4건 / 5~9건 / 10~29건 / 30건 이상 |
| 7 | 여러 공고가 공통으로 요구하는 기술을 따로 정리해 본 적이 있나요 | 없다 / 머릿속으로만 / 메모나 표로 정리했다 |
| 8 | 공고를 보고 공부할 것을 정할 때 어려웠던 점 (최대 2개) | 공고마다 표현이 달라 공통 요구를 모르겠다 / 필수와 우대를 구분하기 어렵다 / 대부분 경력직 공고라 신입 기준을 모르겠다 / 볼 공고가 너무 많다 / 무엇을 공부해야 그 요구가 채워지는지 모르겠다 / 어렵지 않았다 / 공고를 보지 않아서 모르겠다 |
| 9 | 지금 다룰 수 있는 기술 (모두 선택) | Python / Java / Linux / Git / SQL / Docker / AWS / Kubernetes / 네트워크 기초 / CI/CD / 해당 없음 |
| 10 | 클라우드(AWS 등)를 써 본 경험 | 없다 / 수업·실습에서만 / 개인 프로젝트를 배포해 봤다 / 인턴·실무에서 써 봤다 |
| 11 | 인턴·현장실습·대외활동 같은 일경험을 구할 때 지역 때문에 어려웠던 적이 있나요 | 5점 척도(전혀 없다 ~ 매우 그렇다) + 어떤 일이었는지(선택, 한 줄) |
| 12 | 최근 6개월 동안 취업 준비에 쓴 유료 강의·자격증 비용 | 0원 / 10만 원 미만 / 10~30만 원 / 30~50만 원 / 50만 원 이상 / 답하지 않음 |
| 13 | AWS Skill Builder의 무료 디지털 과정을 알고 있나요 | 모른다 / 이름만 안다 / 들어 봤다(수강) |
| 14 | 11/18(수)~11/20(금)에 10분 동안 화면을 써 보고 의견을 줄 수 있나요 | 아니오 / 예 → 연락받을 방법(오픈채팅 닉네임 등) |

- 9번의 선택지는 화면의 보유 기술 선택과 맞춘다. 화면 목록이 바뀌면 함께 고친다.
- 9·10번으로 페르소나 가정("Python·Linux·Git은 다루지만 클라우드 실무 경험이 없다")이 실제 학생과 맞는지 본다.
- 11번은 조사용이다. 서비스는 지역을 입력으로 받지 않는다.

## 5. 본 테스트 뒤 질문지 (2분)

[`user-test.md`](user-test.md)의 과제 3개와 마무리 질문 2개가 끝난 뒤에 준다. 진행자는 답을 유도하지 않는다.

| 2 | 그 기술이 왜 필요한지 화면의 근거(공고 n건 중 m건, 근거 문장)를 보고 납득했다 | 5점 척도 | E2 |

| 4 | 평소 방식으로 같은 결론을 내려면 얼마나 걸렸을 것 같나요 | 10분 미만 / 10~30분 / 30분~1시간 / 1~3시간 / 하루 이상 / 못 했을 것 같다 | E3 |

- 과제 1의 걸린 시간은 기록자가 잰다. 3분 목표와 비교한다.

## 6. 결과 정리와 한계

- 결과는 `docs/user-test-results.md`에 적는다. 사전 설문은 문항별 응답 수, 본 테스트는 사람별 기록(P1~P5)과 과제별 성공 수.
- 숫자는 응답 그대로 쓴다. 인원이 적으므로 비율(%)이 아니라 "n명 중 m명"으로 적는다. 숫자나 반응을 지어내지 않는다.
- 발표와 결과 문서에 범위와 한계를 함께 적는다.
  - 범위: 충남대 컴퓨터융합학부 3·4학년 n명, 조사 기간, 모집 경로
  - 한계: 한 학교 한 학부의 응답이다. 팀원의 지인이 섞여 긍정적으로 답했을 수 있다. 관심 직무가 클라우드·AI가 아닌 응답자도 포함된다(2번 문항으로 나눠서 본다)
